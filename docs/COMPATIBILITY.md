# 客户端版本与旧文件兼容

## 当前结论

本地转换的真实客户端验证范围是 **QQ 音乐 22.71 x86**。原生桥接、安装器和自动恢复已有实现，但仍需要真实下载与客户端重启的端到端验收。

| 层次 | 已实现的机制 | 当前验证 |
| --- | --- | --- |
| 进度卡片和设置 | GF 原生框架承载入口、HTML 控件和透明卡片纹理；绑定原生内容区布局 | 22.71 x86 已实机显示入口、设置与右下角卡片；最新悬停、双击、入场动效和连续样式切换修正待复测 |
| 下载完成事件 | 仅在 QQ 音乐 UI 线程接入；观察两个目标模块的 Win32 文件复制 / 移动导入 | 独立宿主验证四种操作；真实下载事件待联调 |
| 本地密钥库 | 核对 CommonFunction.dll SHA-256 后，调用已知接口；只读指定 MMKV 存储 | 22.71 x86 的真实下载验证 |
| 新文件格式 | musicex V1 文件尾、对应资源密钥、完整音频校验 | FLAC 已实测；OGG 仅实现校验 |
| 旧文件格式 | QTag 与 QMC2 V1 的文件内密钥 | 原创 FLAC 夹具逐字节一致；没有旧客户端实测 |
| 路径自动识别 | 默认下载目录、已有记录、新下载事件学习；启动时自动补处理 | 隔离夹具验证启动补处理、修改目录后学习及回填 |
| 安装与回退 | 用户目录版本文件、完整性校验、保留上一版、损坏回退及同版本修复 | 15 项隔离测试；本机已安装，重启和升级全流程仍待验收 |

M4A、MP3 和 QMC1 暂未支持。支持旧文件格式不等于所有旧客户端均已适配。

## QQ 音乐更新时

程序和接入 DLL 安装在当前用户目录，后台代理从正在运行的 QQMusic.exe 获取实际路径。客户端安装目录变动后可重新识别，不需要依赖客户端更新时可能被移除的 msimg32.dll。

下载接入只观察成功的系统文件操作，不依赖客户端代码的固定地址；保留已有第三方拦截，停用时恢复自己替换的导入项。原生界面使用私有 COM 接口，必须同时匹配 GF.dll、QQMusic_GFWrapper.dll 和 Common.dll 的已验证 SHA-256；未知版本停用该界面，仅记录到运行状态等待适配，下载事件仍可照常接收。不能将“同为 22.x”视为界面 ABI 相同。

本地密钥接口是更严格的一层：只允许已验证的组件指纹。遇到未知组件，新版下载任务保留等待适配；文件内自带密钥的已支持旧格式仍可处理。没有在线适配源时，不会假装已经拿到新版接口。

研究参考为提交 `6fbf21bc6606b40f1804517e37948ff1504da4a1`：

QQ 版后续的在线更新也应按客户端版本范围、架构和发布通道选择，并为旧客户端保留兼容版本。**当前在线兼容清单、更新选择器和自动下载服务尚未实现。**

## 新增适配的验收依据

1. 核对客户端架构、组件指纹、本地接口调用约定与存储结构。
2. 在真实下载完成后检查最终路径事件，不把“DLL 能加载”当成下载事件已验收。
3. 检查整曲音频、标签、可用的本地封面和源文件不变。
4. 检查重启、目录变化、缩放、停用和卸载。
5. 分别记录真实客户端实测与合成夹具测试，更新本文件和验证记录。
